# 验证、发布和交接

## 验收分层

1. **结构**：节点/边/变量引用、分支出口、类型、路径上限、模型参数、候选差异。
2. **运行**：节点真实执行、工具入参/返回、会话状态和未展开引用。
3. **业务**：客户已给信息是否被接受、追问是否明确、答非所问后能否推进、是否触发正确业务动作。
4. **发布**：发布前版本未被并发修改，发布后配置与候选一致。
5. **展示**：节点标题/描述/变量释义和画布可读性，未看界面时不声称视觉验证通过。

测试范围和风险成比例。小改动不必每次全量测试；影响公共事实提取、状态、留资或工具入口时，应覆盖受影响分支及原本正确的相邻行为。用户指定“不测试”时不跑运行验证，报告写未测，结构与保存回读仍需要。

## 对话用例

针对项目服务范围安排多角色、多产品、多轮输入，按需要覆盖：补充、纠正、反问、答非所问、未知/拒绝、确认、取消、切换需求、重复消息、旧会话续聊、多语言、渠道差异与工具失败。

每条用例说明初始状态、输入、预期行为、实际回复、执行路径、关键字段和工具动作。不要只断言包含某句话；不要把一次通过当作模型永久稳定。模型不稳定风险大的关键用例可重复，但遵守用户指定次数。

输出可按“通过 / 未通过 / 环境受限 / 未执行”归类。隔离格式测试不能称为完整业务回归；演示用例不能替代真实回归。

## 副作用控制

模型、解析器单节点验证优先与业务连线隔离；直接调用工具、赋值器、循环或完整聊天可能造成状态或外部变更，必须明确范围。测试身份与联系人使用明确测试值，避免发送到真实客户；名称加“测试”不等于获得真实推送授权。

能使用已有测试环境、沙箱或已授权的替身就使用，不擅自新建Agent或更换生产推送目的地。临时改动要备份、标记并恢复；发现并发编辑不强行恢复整份旧快照。

## 发布清单

- 当前任务明确授权发布到准确应用。
- 原始草稿与已发布版已分别备份，回滚文件确实可读取。
- 改动范围和保留项相符；没有顺带发布他人未发布改动。
- 必需结构检查通过，平台能力已确认；测试/未测情况如实记录。
- 提交前重新读取草稿，与预期基线一致。hash只是平台并发信息，内容比较也需要。
- 保存回读一致后，发布前再次确认没有并发变化。
- 发布后读取已发布版，比较所有业务字段；布局显示状态可明确作为非功能差异，但不悄悄忽略模型、Prompt、变量、工具或边。

附带脚本能检查多次读取之间的一致性，但平台发布接口若不支持原子版本前提，最后一次读取与发布之间仍有竞态窗口。多人同时编辑时协调短暂发布窗口，不能宣称脚本完全消除并发风险。

## 发布结果不确定

POST超时不代表未执行。先只读回查草稿/已发布版/业务事件，不能立即重发发布或业务工具请求。若保存成功但回读不一致，停止发布；不要自动删除节点或补大量默认值。

回滚也属于明确的写操作。确定回滚版本、当前草稿保护方式、变量及旧会话兼容之后执行；不能因为验证失败就无条件用整份旧工作流覆盖用户后续编辑。
